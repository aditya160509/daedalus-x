# T07 — AETHER Design Studio
**Model:** DeepSeek V4.1 Flash Free · **Date:** 2026-11-01 · **Status:** review

## Built
- **Studio Render (default)** — `components/viewer/design/StudioStage.tsx` and `studio.ts`: per-group material overrides (team-colour clearcoat paint on the body, satin wings, rubber wheels, brushed cartridge metal), a four-Lightformer softbox environment (`Environment resolution={256}`, no HDR download), `AccumulativeShadows temporal frames={60}` with `RandomizedLight amount={8}`, and a low-strength `MeshReflectorMaterial` floor (`mirror 0.3`, `mixStrength 5`, `resolution 512`). Every material and light value is a named export in `studio.ts`.
- **Turntable** — `DesignCamera.tsx` rotates the orbit by `TURNTABLE_DEG_PER_S × delta` (6°/s) instead of using OrbitControls' frame-rate-dependent `autoRotate`. Because the camera moves and the car stays still, the accumulated contact shadow remains valid.
- **Engineering mode** — neutral `MeshStandardMaterial` colours per force group, drei `<Edges threshold={20} lineWidth={0.7}>` on every mesh (explicit geometry, with a matrix-tracking group so exploded parts keep their edges), and the measurement grid at the model floor.
- **Exploded view** — 0–1 slider. Each top-level part moves along `(part centroid − car centroid) × k` using `maath/easing.damp3` with a 0.18 s smooth time. Labels appear above 0.3 via drei `<Html>` and follow the eased part position frame by frame.
- **Dimensions** — `Dimensions.tsx` draws length, width and height lines outside the display-mesh bounding box with 3D cone arrowheads and mm labels. The viewport caption says “Dimensions approximate (display mesh)”.
- **Measure tool** — click two points; each click raycasts a mesh and snaps to that mesh's nearest world-space vertex. The 3D dashed line and midpoint label show distance; `MeasureHud` shows distance and Δx/Δy/Δz and states “Approximate (display mesh)”.
- **Part inspector** — name, group, mesh count, triangles, display-mesh bounding-box deltas (mm), and the matched import-record volume in cm³. Parts with a `not watertight` warning in `geometry.json` show “not watertight” instead of a volume; per-part warnings are listed. Duplicate labels (the four axle bushes) are matched by bounding-box centre.
- **Design switcher** — `/v1/designs` dropdown, plus side-by-side compare of two designs with a shared camera bus (`cameraBus`). A owns turntable, selection, measure and snapshot; B follows the orbit pose. Preset framing uses the primary model's frame so both cameras start identically.
- **Snapshot** — `SnapshotBridge.tsx` registers a capture that renders one frame at `2 ×` the current drawing buffer, calls `gl.domElement.toDataURL("image/png")`, and restores the renderer. The Canvas uses `preserveDrawingBuffer: true`. In compare mode the PNG is the primary canvas.
- **Data plumbing**
  - `src/daedalus/api/engineering.py`: new `GET /v1/designs/{id}/geometry.json` returning the full import record (transform, dimensions, parts with volume/bbox, groups, warnings) and 404/422 on missing or malformed records.
  - `src/lib/api.ts`: `DesignPart`/`DesignGeometry` Zod schemas and `getDesignGeometry`.
  - `src/lib/gltf.ts`: `PartNode` now carries `label`, `group`, world-space `bboxMin`/`bboxMax`/`centroid`; `LoadedModel` carries `bounds` for framing and dimension lines.
  - `useDesignModel.ts`: loads display GLB and geometry record together; a failed geometry record does not block the mesh.
- **CarViewer split** — deleted `components/viewer/CarViewer.tsx`. The design viewer is now `components/viewer/design/*`; `CameraPreset` moved to `components/viewer/types.ts` so the flow viewer and the design studio share one type.
- **Import** — the existing drag-and-drop and file-picker GLB path is preserved. A local file clears the design id, compare state and geometry record, so the inspector never claims volume or warnings for an unrecorded mesh.

## How to run / see it
```bash
uv run daedalus-api                 # :8000
pnpm --dir apps/cockpit dev         # :3000 → /design
```
The workspace opens on `orbit_baseline` with Studio mode, dimensions on, and the exploded slider at 0. Drag the orbit, switch to Engineering for edges/grid, raise Explode to see labels, click Measure then two points, toggle Compare (two designs are present), and press PNG.

## Decisions and deviations
- **Camera orbit turntable, not car rotation.** Rotating the car would invalidate the baked contact shadow; orbiting the camera gives the same presentation and keeps shadows and the reflective floor correct.
- **Delta-based turntable.** OrbitControls' `autoRotate` is per-frame, so it drifts with refresh rate. The manual azimuth step is exactly 6°/s.
- **Dimensions default on.** They are part of the design review, not a hidden debug view; the caption and the header's `estimated` provenance badge make the accuracy claim explicit.
- **Measure snaps per clicked mesh.** Snapping to the nearest vertex of the whole scene would jump to another part across a gap; per-mesh snapping stays on the surface the user picked.
- **Selection and measure live on canvas A in compare.** B is a visual reference; allowing two independent selections would make the single inspector ambiguous.
- **Engineering edges use drei `<Edges threshold={20}>` with explicit geometry.** The GLB nodes are already in the scene, so a small matrix-tracking group is used instead of reparenting meshes.
- **Volume is withheld for non-watertight parts** even though the import record carries a numeric volume; the warning is the more honest statement.
- **Local GLB import drops the geometry record.** There is no provenance for volume or warnings on an arbitrary file, so the inspector says so rather than guessing.

## Known gaps (for reviewer)
- No browser or visual QA and no GPU profiling, per the build pack. The look of the paint, softbox highlights, accumulated shadow and reflective floor still need eyes; the cost of `AccumulativeShadows` + `MeshReflectorMaterial` at 1440p is unmeasured.
- The reference GLB has no materials or textures, so Studio mode is entirely an override. Team livery textures, decals and multi-material parts are not supported.
- Dimensions and measurements use the tessellated display mesh; the `geometry.json` length/width/height and volume are import-record values and may differ slightly.
- Duplicate labels are matched by bounding-box centre; two parts with the same label and coincident boxes could still mismatch.
- Snapping is to the nearest vertex of the clicked mesh, so the reported point can be up to roughly one triangle edge from the click. The HUD calls this approximate.
- Snapshot uses `toDataURL` at 2× the drawing buffer; a very large window could hit browser canvas limits, and there is no explicit size guard.
- Compare uses two separate WebGL contexts. That is fine for a pair, but it is not a general N-way comparison.
- A local GLB has no import record, so the inspector shows no volume, CAD match or watertight warning for it.

# A06 — CAD rule overlay: colours and value/limit dimensions

**Status:** built (software). Unsupported/manual rules stay manual, and every annotation is
labelled CAD.

## What changed

- `vendor/chili3d/packages/web/src/daedalusBridge.ts` (vendored AGPL-3.0, patch regenerated):
  - new `daedalus:rules` message with a validated list (≤128 entries, known state, x/y/z axis,
    finite values, bounded strings);
  - matched named parts receive a document material: red `fail_cad`, amber `at_risk`, green
    `pass_cad_only`; multiple rules on one part use the worst state;
  - the original material id is stored and restored, and annotations are removed, on every new
    rule message and on `daedalus:clearRules`;
  - a real `DimensionAnnotation` is drawn along the host-declared axis with the text
    `<value> / limit <limit> <unit> · CAD`;
  - rules without a declared axis, or without a bounding box, are reported in `unavailable`
    instead of being given a guessed attachment. Manual rules are not coloured.
- `apps/cockpit/src/lib/cadFocus.ts`: `CadRule`, `applyCadRules` (20 s timeout, same-origin
  request/reply by revision) and `clearCadRules`.
- `apps/cockpit/src/app/design/CadFrame.tsx`: applies rules after the iframe loads, re-applies on
  rule/revision change and clears when the rule set becomes empty.
- `apps/cockpit/src/app/design/DesignStudio.tsx`: fetches `/v1/forge/checks` for the open design,
  flattens each check to its named parts, and picks the nearer stated limit.
- `src/daedalus/forge.py`: `Check.axis` and a deliberately small measure→axis map (`_span`→y,
  `_chord`/length/wheelbase/overhang→x, `_height`/`_bottom`→z). Clearance, diameter, mass and
  manual rules intentionally have no axis.
- `apps/cockpit/src/lib/api.ts`: `RuleCheck.axis` optional enum.
- `patches/chili3d.patch` regenerated; `apps/cockpit/public/cad` rebuilt from the vendored source
  (`npm run build` → `dist/` copied; only `main.js` changed).

## Gates and limits

- No live browser acceptance: the local dev server previously died with exit 137, so the iframe
  overlay was not clicked through or screenshotted. Build success and bridge unit tests are not a
  visual pass.
- The dimension line spans the matched part's bounding box along the declared axis. It is a CAD
  value/limit annotation, not a feature-level measurement and not an inspection record. A physical
  measured value must come from an inspection record; nothing here substitutes for one.
- Part matching uses the existing normalised-name rule, so CAD names must still match FORGE part
  labels.

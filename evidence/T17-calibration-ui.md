# T17/T09 Bayesian calibration workflow

Race → Calibration previews uploaded race-timing CSV/XLSX through the existing unit-aware import endpoint without committing it. Users provide calibration track length, per-run timing SD and fallback mass (file mass takes precedence), edit the log-normal prior medians and shared log SD, noise/offset prior scales and density, and optionally upload a thrust CSV; the Race estimated curve is clearly labelled as an estimate. Users must confirm the imported values are car-only times and any held-out rows are independent. Reaction values are previewed and not subtracted. An optional separate held-out timing file is scored only after fitting to calibration rows; no values are generated for missing files.

`POST /v1/calibrations/bayesian` calls the existing Bayesian adaptive-importance-sampling core with bounded workloads (300 particles, 2 adaptation stages, 300 draws, seed 0), returning posterior summaries, effective sample size, warnings, and predictive median/90% interval/error for supplied held-out runs. The UI shows information gain as prior variance reduction, not proof of identification. These calculations are ephemeral: uploads and posterior are not committed to evidence and are not applied to the Race model. Each file has one entered track length and timing SD; density is shared; per-run mass is supported. Training and held-out independence relies on user confirmation.

Checks: `uv run pytest -q tests/test_bayes_calibration.py` (5 synthetic core tests) and `tests/test_api_bayesian_calibration.py` (API wiring and held-out separation) passed. Frontend `tsc --noEmit` and focused oxlint, Python ruff and formatting checks passed. Existing TanStack Query, Zod and project UI components were reused; no dependency or upstream code added.

Scientific gates remain: real instrument-backed runs under varied conditions, known timing definition and thrust, independent held-out measurements, assessment of sampling quality and model discrepancy. No physical validation or browser check was performed. The limited particles may leave the posterior approximate, particularly when effective sample size is low; use warnings rather than treating the result as an acceptance claim.

Parent review added a nonblocking single-calibration gate per API process to avoid concurrent memory-heavy posterior fits, with an overlap-rejection test. Input fieldsets are disabled while fitting/planning so a late result cannot silently appear beside edited assumptions.

# T02 — Durable local queue and CFD launch controls
**Model:** Codex (GPT-6) · **Date:** 2026-11-01 · **Status:** review

## Built
- `src/daedalus/jobs.py`: local SQLite queue, atomic UPDATE…RETURNING claims, one CFD-family operation at a time, two subprocess slots, process-group cancellation (TERM then KILL), dead-process recovery, output reservations, CPU cap, bounded byte-offset logs and real solver-stage progress.
- `src/daedalus/contracts.py`: frozen `LocalJob` queue snapshots using existing `JobState`. Queue transitions are mutable operational records, separate from immutable scientific evidence.
- `src/daedalus/api/jobs.py`: discriminated per-kind requests, submit/list/get/cancel/log endpoints, path and existing-output checks. API only enqueues; no solver is launched in a request.
- `src/daedalus/cli.py`: jobs worker/submit/ls commands and lazy geometry imports. Four execution kinds: cfd_run, cfd_viz, geometry_import, montecarlo_batch.
- `apps/cockpit/src/components/jobs/*`: New run dialog and polling jobs drawer with approval, state/elapsed time, bounded log tail, solver progress, cancel confirmation and CFD-list invalidation. Empty Simulate workspace still exposes queue controls.
- Local Radix-based Dialog/Sheet house components; no dependency or UI library migration.
- `.gitignore`: queue DB, journals and operational logs/results excluded.
- Added jobs worker entry to the existing `../.claude/launch.json`. That parent file is outside this Git repository, so it is updated locally but not in the repository commit.

## How to run / see it
```bash
uv run daedalus jobs ls
uv run daedalus jobs submit cfd_run --design orbit_v2 --run orbit_next_quick --fidelity quick
uv run daedalus jobs worker
```
Use `/simulate` for New run / Jobs. Submit enqueues and returns HTTP 202; start the separate worker only after closing UI dev servers/browser on this Mac. These example CFD submission/worker commands were not executed against production data in T02. No CFD case was run. Tests execute a tiny real numerical job in a temporary data root.

`DAEDALUS_DATA` chooses a separate workspace for queue and artifacts. Output IDs match `^[a-z0-9_]{3,64}$`; geometry source files must stay under that workspace. Existing or already-reserved new output IDs are rejected.

## Decisions and deviations
- Followed the updated repo build pack (Pyrefly/pnpm/Oxfmt), not obsolete mypy/npm commands in the original pasted prompt.
- cfd_viz shares the CFD resource lock to avoid simultaneous heavy solver/VTK operations. Other kinds can use the second subprocess slot.
- MPI ranks capped to min(requested, 8, max(1, cpu_count−2)); clamp again at execution.
- The task's states stay queued/running/succeeded/failed/cancelled. Cancellation holds the running resource lock until process termination and records its request in error, avoiding a second CFD launch during grace time.
- CLI can submit all four kinds; Monte Carlo uses `--request` JSON. No arbitrary shell/command API is exposed.
- The shadcn CLI prompted for a new component library despite --yes. Reused installed Radix Dialog with minimal local house wrappers instead of selecting a different UI library or adding dependencies.
- Global run directories remain never-overwritten. Queued output reservations persist after failure/cancellation; choose a new ID.
- Stdlib execution/queue logic reuses frozen Pydantic contracts; the numerical batch worker lazily reuses existing validated race API models/functions rather than duplicating physics.

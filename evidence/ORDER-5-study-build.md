# ORACLE study build and observation integrity

Pit Wall's real selected unit-cube recommendation can now be built with the installed Apache-2.0 build123d/OpenCascade machinery. The baseline's overall dimensions constrain the study envelope. One canonical generator controls angle, taper, nose height and rear chord; cheap study-family filtering constrains rear chord to 15–25 mm before acquisition ranking. This filter is not a proof of all FORGE rules. The generator produces named solids, writes STEP and uses the existing geometry importer for CFD STLs and the display GLB. The import uses nose -X/up +Z to preserve engineering downstream +X.

`POST /v1/oracle/build-next` records an estimated build123d Design with all four physical parameters, a STEP artifact and an ORACLE manifest artifact containing the baseline geometry hash, generator version and current campaign observation snapshot. The complete generated directory is published after import/FORGE finishes. The response contains all 80 India checks and failed/manual counts. The UI links to the exact new CAD/rules design and passes that design to the existing CFD launch dialog only when there are no failed CAD rules. Builds are serialized per API process. No CFD is automatically launched.

The study family is not a reconstruction of the manufactured car. It lacks engineered halo/tether details and needs geometry, manufacturing, loading and physical verification; failed/manual rule states remain visible. There is no claim of a legal production car or a completed closed loop. Automatic accepted-only CFD feedback, synthetic-vs-physical training separation and the full racing-points objective remain outstanding. The current campaign API still supports explicit manually supplied observations; they are not independently accepted CFD results.

Observation ingestion now rejects non-finite/out-of-bounds values instead of silently clamping them. Campaign writes serialize read/append under a file lock and atomically replace fsynced JSON, avoiding lost concurrent updates or half-written revisions.

Validation: real CAD endpoint test built a valid study, imported STEP/GLB, returned 80 checks, verified recorded parameters/provenance and artifacts, rejected out-of-family input and cleaned staging directories. Focused ORACLE tests cover invalid observations, parallel appends and family constraints; TypeScript, changed-file Oxlint and Python Ruff pass. No browser, CFD, final acceptance or memory benchmark ran. No new dependency or copied upstream application code was introduced; actual existing build123d/OpenCascade and Query/Zod/Base UI components are used.

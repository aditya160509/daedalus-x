# T06 two-run surface ΔCp

Wind Tunnel → Flow uses the global run picker as the base and a second completed-run selector for the other case. The viewer requests a strict comparison and displays ΔCp = Cp(other) − Cp(base), a zero-centred diverging legend, both run IDs, source acceptance states, field times, freestream speeds, simulated provenance, geometry digest and frame. A VTP and companion source metadata JSON are available to download. Errors from incompatible or incomplete cases remain visible; neither solver success nor this comparison is presented as physical validation.

Compatibility is intentionally conservative: both cases must use the recognized `daedalus-halfcar-v4` engineering-metre frame, have completed solver runs and identical per-patch STL source hashes, identical initial pressure boundary files, positive finite reference speeds, and kinematic-pressure dimensions with zero outlet references in both initial and latest solved fields. Point pressure must be finite on each patch. Each Cp is normalized by its own 0.5 U∞². The generated indexed surface points and faces must match exactly; otherwise the server rejects the pair. There is no nearest-neighbour mapping or interpolation. The VTP endpoint computes on demand and sets no-store; it is not cached. Metadata and VTP field times and source digest are checked for consistency in the viewer.

Optional vtk.js layers now abort cancelled fetches and dispose their actors, mappers, lookup tables, data and readers when removed or when the viewer unmounts. No new dependencies or copied code were added; existing PyVista/VTK, vtk.js and Zod are used.

Checks: `uv run pytest -q tests/test_vtk_compare.py` passed (3 synthetic tests covering source/frame/reference rejection, normalized ΔCp, mismatched or nonfinite arrays, API output and unsafe IDs). Frontend TypeScript and focused oxlint completed without errors (vtk.js import-style warnings remain); Python ruff/format passed. No CFD, real accepted-run comparison or browser/GPU validation was performed. Existing runs with older/unknown frame templates, changed source geometry, different surface meshes or unsupported pressure serialization are rejected; a compatible real pair has not been established. The strict comparison does not cover design-to-design mapping, Δwake or Δforces.

Parent review: native VTK field exports/comparisons now serialize per API process to avoid overlapping large field loads. Comparison releases each full source field after extracting its bounded surface. Base and optional vtk.js resources, replaced colour maps and cancelled fetches have explicit cleanup; memory improvements are structural, not a measured production-memory claim.

# T04/T06 wake planes and Q surfaces

The active vtk.js Flow viewer now requests optional VTK XML layers from the selected run's solved OpenFOAM field. `vtkexport.py` uses PyVista's native transverse slicing at x/L = 1, 1.5 and 2, clipped to the wake region, and `compute_derivative(qcriterion=True)` plus native contouring for Q/(U∞/L)² = 50 and 200. Wake planes show Ux/U∞; Q surfaces show |U|/U∞. Both are mirrored from the half-model and cached with export version 3. Viewer controls lazily load each layer, show loading/error/empty states and legends, and offer VTP downloads. The panel displays the source run ID, existing run acceptance state, speed, car length and simulated provenance; it does not turn a rejected or pending source into an accepted one. x/L is relative to the case coordinate origin.

The fixed Q levels and bounded/decimated surface are visual diagnostics, not proof of a vortex or a measured quantity. Planes can be empty if outside the solved domain or selected wake region. No comparison, ΔCp, Δwake, vorticity colouring, variable Q level or momentum-deficit calculation was added. No CFD case was run and no accepted real run or browser was verified in this work.

Checks: `uv run pytest -q tests/test_vtk_insights.py` passed (2 tests using synthetic analytic rotation and uniform fields, including VTP round trips and empty cases); Python ruff/format and frontend `tsc --noEmit` passed. Focused oxlint completed with existing vtk.js default-import and local-scoping warnings, no errors. Existing PyVista/VTK and vtk.js were used; no external source code or dependency was added.

Parent review: native VTK field exports/comparisons now serialize per API process to avoid overlapping large field loads. Comparison releases each full source field after extracting its bounded surface. Base and optional vtk.js resources, replaced colour maps and cancelled fetches have explicit cleanup; memory improvements are structural, not a measured production-memory claim.

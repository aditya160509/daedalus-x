# R1 — Saved-study identity review fix

Review finding: `evidence/REVIEW-EASY-SPRINT-2026-11-04.md` P2 — "held-out identity omits actual targets and loses row associations". Two one-row studies with measured times 1.5 s and 1.9 s produced the same identity and both read "Same row signature; source-file hash unavailable".

## Changed

- `src/daedalus/api/data.py` — `SourceFile.role` (`training`, `held_out`, `thrust`, `other`, optional), persisted as `CalibrationStudy.source_roles`; `_decode_sources` carries the role; the study detail endpoint returns `role` per source (blank/absent means role not recorded).
- `src/daedalus/contracts.py` — `CalibrationStudy.source_roles: tuple[str, ...]`, parallel to `source_labels`, so a saved study can state the role rather than have it inferred later.
- `apps/cockpit/src/lib/api.ts` — source schema accepts the nullable `role` enum.
- `apps/cockpit/src/components/race/CalibrationPanel.tsx` — uploaded timing files are labelled `training` / `held_out` explicitly instead of relying on array position.
- `apps/cockpit/src/lib/calibrationCompare.ts` — identity schema `2` built from the actual stored held-out inputs and measured targets: row order, per-row condition (`track_m`, `sigma_s`, `mass_kg`, `reaction_s`), the measured value, and the shared thrust curve / density. Model predictions are excluded because two models may legitimately predict different values on the same test set. Only an explicit `held_out` source role supplies a supplementary hash; file order is never a role.
- `apps/cockpit/src/lib/calibrationCompare.test.ts` — changed-target, swapped per-row conditions, legacy unknown role, `other`/`training` role, verified matching hash, differing hash and misaligned-row cases.
- `tests/test_api_bayesian_calibration.py` — posts `role: "held_out"` and asserts it round-trips through the detail endpoint.

## Behaviour

| Situation | Comparability shown |
|---|---|
| No held-out rows | Not evaluated — no held-out rows |
| Stored inputs/results row counts differ | Not comparable — stored held-out rows are misaligned |
| Different measured targets or row/condition order | Not comparable — different scored held-out rows |
| Same rows, no explicit held-out role/hash | Same scored held-out rows; held-out source role/hash unavailable |
| Same rows, explicit hashes differ | Comparable scored rows; held-out source hash differs |
| Same rows, explicit hash matches | Comparable held-out set (source hash verified) |

Legacy studies saved before this change keep an empty role and remain honestly unknown; they can still match on exact scored rows, but not claim a verified file identity. MAE/RMSE are computed only from stored held-out errors, so an empty set is `null`, never zero.

## Limitations

A source hash verifies the uploaded file, not that the file matches the row values; both checks are reported separately. Existing studies cannot gain a role retroactively without re-running the fit. This is saved-study comparison hygiene, not independent physical validation.

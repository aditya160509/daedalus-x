# T09: importers, units and calibration

**Status:** review. Claude Opus 5.5 recovered and fixed an abandoned, uncommitted implementation (2026-11-01).

## State found
About 1,600 uncommitted lines across `importers.py`, `calibration.py`, `api/data.py` and three test files. 10 tests failed, there were 26 Pyrefly errors and 37 ruff errors, and the API could not start because `python-multipart` was missing.

## Fixed
- **Dependency:** added `python-multipart`, which FastAPI needs for multipart uploads.
- **Unit headers:** `time_ms` and `force_n` were not recognised. Underscore aliases never matched the normalised names. The header parser now handles `x [u]`, `x (u)` and `x_u`.
- **Calibration noise:** the fit used reaction time as the timing noise (σ). It now uses `sigma_s`.
- **Optimiser:** steps were unscaled (CdA ~1e-3 alongside scale ~1), so the solver stalled at bounds. Steps are now scaled per parameter, with an explicit `diff_step`.
- **Calibration closures:** loop closures captured the wrong resample (B023). They now bind with `functools.partial`.
- **API:** `GET /v1/calibrations/{id}` had lost its `if model.kind != "titan"` guard (dead code after a raise).
- **API:** a production `assert` replaced with an HTTP 500.
- **API:** `CalibrationFitResponse` typing rejected the string fields.
- **Mass import:** the warning was a bare string rather than a 1-tuple, so it would have split into characters.
- **Imports:** a header column width bug, where the column count came from the longest header string.
- **Tests:**
  - The CSV parser fixture never matched the importer's columns.
  - Records were created without their Project and Design references.
  - The "append" test reused record ids.
  - A misspecified fixed-scale fit was expected to recover the true value.
  - A Crr point-recovery assertion was physically unrealistic. Rolling force is about 1% of drag at race speed, so Crr is now checked through its bootstrap CI.

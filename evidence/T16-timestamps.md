# T16 third-party timestamps

The sealed prediction panel can explicitly submit the seal hash to the existing FreeTSA RFC 3161 endpoint and check stored response availability. It shows authority/network errors, the response's claimed time, and states that receiving a response does not verify its signature. The server now exposes status and an explicit verification endpoint for the latest stored response. Verification checks the stored artifact's content hash and the prediction seal, then invokes OpenSSL against `DAEDALUS_TSA_CA_FILE`, an operator-configured trusted authority CA bundle. The interface reports the actual verification result and disables verification until the configured file exists. Only the hash is submitted, never the prediction. The existing local sealing time is not presented as third-party evidence.

Checks: `uv run pytest -q tests/test_anchor.py` passed (8 tests, with a fake TSA and a deliberately untrusted response); focused Python ruff, frontend TypeScript and focused oxlint passed. The test verifies the unavailable-trust and failed-signature paths, not a live authority or valid certificate chain. No external authority was contacted. A trusted CA bundle and independently verifiable real TSA response remain required.

## 2026-11-02 — persisted verification results and history

- `contracts.TimestampVerification` (append-only, `tsv_*`) records each check with the exact `prediction_id`, `token_artifact_id`, the trust bundle `ca_artifact_id`, the verdict, the captured OpenSSL output, the command that reproduces it, the OpenSSL version and the TSA's claimed time. The store's reference check makes a missing token, bundle or prediction fail the insert rather than leave an orphan.
- `anchor.verify_stored_timestamp` runs the same `openssl ts -verify` check as before, then writes the record. The CA bundle is stored as an artifact and reused by content hash, so the bytes a judge would need are recoverable from the evidence store.
- `GET /v1/analysis/predictions/{id}/anchor` now returns `verification_count` and `latest_verification`; `GET .../anchor/history` returns stored responses plus every recorded verification; `POST .../anchor/verify` returns the persisted record instead of a transient object. The Pit Wall timestamp panel lists the history with verdict, TSA time, token, CA artifact and the command/output.

# R2 — Export snapshot freshness review fix

Review finding: `evidence/REVIEW-EASY-SPRINT-2026-11-04.md` P2 — "process-lifetime Git identity". `source_identity.code_snapshot()` was wrapped in `functools.lru_cache`, so every report/sheet/summary exported by a long-lived API process reported the commit captured at first use, even after later commits or local edits.

## Changed

- `src/daedalus/source_identity.py` — removed the cache. `code_snapshot()` now captures a fresh bounded, offline snapshot per export and returns `{commit, dirty, state, captured_at}`. `source_identity()` embeds that block; `short_commit()` keeps the readable dirty/clean label. Missing `.git`, a missing `git` binary, a non-zero exit or a 2 s timeout all produce `state: "unavailable"` rather than an invented commit.
- `src/daedalus/report/report.typ`, `sheet.typ`, `summary.typ` — the provenance row reads `#code.label · captured #code.at("captured_at", default: "unavailable")`, so the export states when its code identity was taken and degrades safely if an older identity payload lacks the field.
- `tests/test_source_identity.py` — fresh-snapshot test: the same process exports twice with a changed commit and dirty state and must report both truthfully; plus bounded-call, no-`.git`, full-hash and missing-file tests.

## Behaviour

- Two exports from one API process after a commit now differ: the second reports the new commit and `dirty: true` when the tree has since changed.
- `captured_at` is a UTC wall-clock string from `datetime.now(UTC)` at call time, not process start.
- Git access stays bounded: `shutil.which("git")`, argument-list `subprocess.run`, `timeout=2 s`, `check=False`, no shell, no network.
- `official_rule_pdf_archived` remains `False`; the YAML revision/hash is still explicitly separate from an official PDF identity.

## Checks

- `.venv/bin/python -m pytest tests/test_source_identity.py -q` — 8 passed.
- `.venv/bin/python -m ruff check` / `ruff format --check` on the changed files — clean after removing an unused import.
- `.venv/bin/python -m pytest tests/test_report.py tests/test_forge_india.py -q` — report, sheet and summary templates compiled with the new `captured_at` row.
- `npx tsc --noEmit -p .` — clean (the type change in `api.ts` for R1 also covers R2's payload).

## Limitations

The snapshot proves which local commit produced an export; it does not prove the export left the machine unchanged, does not archive the official rule PDF and is not a trusted timestamp. Run-manifest identity, offline demo and recorded fallback remain separate J10 gates.
